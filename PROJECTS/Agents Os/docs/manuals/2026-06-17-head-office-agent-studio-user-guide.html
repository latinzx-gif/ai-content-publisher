คู่มือการใช้งาน Head Office Agent Studio V1

คู่มือนี้สรุปการใช้งานจริงของแอปจากโค้ดปัจจุบันในโปรเจกต์ SwiftUI ชุดนี้เท่านั้น โดยเน้น workflow ตั้งแต่สร้างโปรเจกต์, นำเข้า PRD, ตั้งทีม/รันไทม์, เดิน task แบบ manual/mock, จนถึงการเตรียม demo และ handoff สำหรับปิดงานภายในองค์กร.

Native macOS • SwiftUI SQLite-backed records Local-first file workflow V1 = manual/mock runtime loop
จำนวนหน้าปัจจุบัน 11 หน้าหลักใน sidebar
Root โฟลเดอร์โปรเจกต์เริ่มต้น ~/AgentStudio/Projects
โฟลเดอร์มาตรฐานต่อโปรเจกต์ 13 โฟลเดอร์ย่อย (00–12) + README
ข้อจำกัดสำคัญ ยังไม่มี autonomous CLI launch จากในแอป

ข้อสำคัญก่อนเริ่ม

  • แอปเวอร์ชันนี้เป็น V1 shell สำหรับการจัดการงานแบบ local-first และ file-transparent
  • Runtime execution ยังเป็น manual/mock — แอปยังไม่ยิง Codex / Claude Code / Gemini CLI อัตโนมัติจากในแอป
  • Agent Library, Skill Library และ Team Builder ตอนนี้รองรับทั้ง create + edit + delete แล้ว แต่ยังเป็นการแก้ record พื้นฐานใน V1 ไม่ใช่ runtime orchestration จริง
  • การปิดโปรเจกต์ถูก gate ด้วย blocking human requests ต้องเหลือ 0 ก่อน

ภาพรวมระบบ

Head Office Agent Studio เป็นแอปควบคุมงานภายในสำหรับจัดการโปรเจกต์ AI/automation แบบ native macOS โดยผูก 3 แกนเข้าด้วยกัน: ข้อมูลใน SQLite, โฟลเดอร์โปรเจกต์จริงบนเครื่อง, และการไหลงานที่ต้องผ่านคนก่อนปิดหรือยิงงานเสี่ยง.

1) Project + Folder

ทุกโปรเจกต์มี record และมีโฟลเดอร์จริงบนดิสก์พร้อมโครงสร้าง 00–12 สำหรับเก็บอินพุต, PRD, runs, reviews, audits, requests, demo, handoff.

2) Agent / Skill / Team / Runtime

ใช้สำหรับกำหนดว่าใครทำอะไร, ใช้ความสามารถอะไร, อยู่ทีมไหน และจะวิ่งผ่าน runtime แบบใด แม้ V1 ยังเป็น planning/manual เป็นหลัก.

3) Task / Request / Demo Handoff

ใช้ขับงานจริงแบบมีร่องรอย ตั้งแต่สร้าง task, ขออนุมัติ, บันทึก log, ขอ input จากคน, ไปจนถึง export เอกสารปิดงาน.

ข้อมูล seed เริ่มต้นที่มีให้

  • Runtime เริ่มต้น: Mock Local Runtime, Codex CLI, Claude Code, Gemini CLI
  • Agent seed 12 ตัว เช่น PM Agent, Product Analyst Agent, Frontend Agent, QA Agent, Audit Agent, Documentation Agent
  • Skill seed หลายประเภท เช่น PRD Writer, Scope Analyzer, Task Breakdown, QA Checklist, Security Audit
  • Team template 3 ชุด: HR Payroll Team, Inventory System Team, AI Content System Team

หมายเหตุ: Runtime ที่เป็น CLI ตอนนี้ยังอยู่ในสถานะ planned/track readiness ยังไม่ execute อัตโนมัติจากแอป

Workflow ทั้งระบบ

1

Create Project

สร้าง project record + โฟลเดอร์จริง พร้อม preview โครงสร้างไฟล์ที่ระบบจะใช้ต่อ.

2

Import PRD

คัดลอกไฟล์ต้นฉบับเข้า workspace, normalize เป็น markdown, และสร้างไฟล์วิเคราะห์ PRD 7 ชนิด.

3

Set Team / Agent / Runtime

เลือกบทบาท, ความสามารถ, ทีม, และ runtime mapping ที่จะใช้กับงาน.

4

Seed / Create Tasks

สร้างบอร์ดงานเบื้องต้นหรือเพิ่ม task เอง แล้วกำหนด agent, runtime, acceptance criteria, dependencies.

5

Manual/Mock Delivery Loop

เดิน task ผ่าน approval gate, running, review, audit, blocked, done โดยไม่ launch CLI จริงอัตโนมัติ.

6

Run Logs + Human Requests

ทุก transition สำคัญถูกบันทึกเป็น log และสิ่งที่ต้องรอคนจะเข้า Human Request Inbox.

7

Demo / Handoff

สร้าง checklist, demo script, handoff checklist, closure summary และปิดโปรเจกต์เมื่อไม่มี blocking requests.

Checklist เริ่มใช้งาน 10 นาทีแรก

  1. เปิดแอปและเริ่มจากหน้า Create Project
  2. ตั้งชื่อโปรเจกต์, project type, owner/client, deadline, priority
  3. ยืนยัน root path หรือเปลี่ยน root ด้วยปุ่ม Choose…
  4. กด Create Project เพื่อสร้าง record และโฟลเดอร์
  5. ไปหน้า Project Dashboard เพื่อตรวจว่าโปรเจกต์แสดงและ health ปกติ
  6. ไปหน้า PRD Import แล้วนำเข้าไฟล์ PRD
  7. ดูว่าเกิดไฟล์ normalized + analysis artifacts ครบ
  8. ไปหน้า Task Board แล้วกด Seed Initial Task Board
  9. ลองเปิด task ใด task หนึ่ง แล้วกด Prepare Runtime Brief
  10. ถ้าต้อง demo/handoff ให้ไปหน้า Demo / Handoff Center เพื่อสร้าง script/checklist/export

คู่มือรายหน้าทั้ง 11 หน้า

1. Project Dashboard

ใช้งานได้จริง

หน้าที่: มองภาพรวมโปรเจกต์ทั้งหมด, ค้นหา/กรอง, เช็กสุขภาพโฟลเดอร์, ดูรายละเอียด, แก้ไขโปรเจกต์, archive และลบ record

  • ใช้เมื่อไร: ต้องการดูสถานะรวม, ตรวจ workspace, แก้ข้อมูลโปรเจกต์
  • ปุ่ม/ช่องสำคัญ: Search, Status filter, Priority filter, Show Details, Edit, Repair Folders, Archive, Delete Record
  • ขั้นตอนสั้น: ค้นหาโปรเจกต์ → กด Show Details → ถ้า missing folders ให้กด Repair Folders → ถ้าข้อมูลงานเปลี่ยนให้กด Edit
  • ข้อควรระวัง: Archive คือเก็บ record ไว้แต่เปลี่ยนสถานะเป็น archived; Delete Record คือลบออกจากฐานข้อมูล

2. Create Project

ใช้งานได้จริง

หน้าที่: สร้าง project record ใหม่และสร้างโครงสร้างโฟลเดอร์จริงบนเครื่อง

  • ใช้เมื่อไร: เริ่มโปรเจกต์ใหม่
  • ปุ่ม/ช่องสำคัญ: Project name, Project type, Client/Internal label, Deadline, Priority, Output goal, Base folder path, Choose…, Create Project, Open Root
  • ขั้นตอนสั้น: กรอกข้อมูล → ตรวจ Folder Structure Preview → กด Create Project → เปิด root เพื่อตรวจโฟลเดอร์จริง
  • ข้อควรระวัง: Project name ห้ามว่าง; slug จะถูกสร้างจากชื่อโปรเจกต์

3. PRD Import

ใช้งานได้จริง

หน้าที่: คัดลอก PRD เข้า workspace, normalize เป็น markdown, และสร้าง artifacts วิเคราะห์ PRD

  • ใช้เมื่อไร: หลังสร้างโปรเจกต์และพร้อมเริ่มตีความ requirement
  • ปุ่ม/ช่องสำคัญ: Project picker, Choose File and Import…, Open Imported Folder, Generated Artifacts, Normalized PRD Preview
  • ขั้นตอนสั้น: เลือกโปรเจกต์ → เลือกไฟล์ PRD → ตรวจ original path, normalized path และ artifact list
  • รองรับไฟล์: md, txt, html, docx, pdf
  • ข้อควรระวัง: ต้องมี project folder ก่อน import; หลัง import สถานะจะขยับเป็น prd_analyzed

4. Agent Library

create + edit + delete

หน้าที่: เก็บ reusable AI worker profiles และ runtime mapping ของแต่ละบทบาท

  • ใช้เมื่อไร: ต้องการเพิ่ม agent profile ใหม่สำหรับใช้ใน task/team
  • ปุ่ม/ช่องสำคัญ: Agent name, Role, Goal, Runtime, Model, Skill names, Output contract, Save Agent
  • ขั้นตอนสั้น: กรอกแบบฟอร์ม → กด Save Agent → ตรวจในรายการ Available Agents
  • ข้อควรระวัง: การแก้ไขตอนนี้ครอบคลุมข้อมูล profile หลัก เช่น name/role/goal/runtime/model/output contract แต่ยังไม่ใช่การควบคุม runtime จริง

5. Skill Library

create + edit + delete

หน้าที่: เก็บ capability package แบบ reusable เช่น workflow, review checklist, output contract

  • ใช้เมื่อไร: ต้องการนิยามทักษะที่ agent จะอ้างอิง
  • ปุ่ม/ช่องสำคัญ: Skill name, Type, Instruction, Workflow, Checklist, Output contract, Required tools, Save Skill
  • ขั้นตอนสั้น: กรอกข้อมูล skill → Save → ตรวจว่า skill ปรากฏในรายการ
  • ข้อควรระวัง: ตอนนี้แก้ไข skill เดิมได้แล้วจากปุ่ม Edit ในรายการ แต่ยังเป็นการแก้ metadata ของ skill ไม่ใช่การรัน skill จริง

6. Team Builder

create + edit + delete

หน้าที่: ประกอบทีมจาก agents, ระบุ lead, workflow และผูกกับโปรเจกต์หรือ template

  • ใช้เมื่อไร: ต้องการกำหนดชุดคน/บทบาทที่จะใช้กับโปรเจกต์
  • ปุ่ม/ช่องสำคัญ: Team name, Purpose, Lead Agent, Members, Project, Workflow, Review rules, Runtime preference, Save Team
  • ขั้นตอนสั้น: เลือก lead + members → ผูก project/template → Save Team
  • ข้อควรระวัง: ตอนนี้สามารถแก้ lead, members, workflow, runtime preference และ project assignment ได้แล้ว แต่ยังเป็น team configuration ของ V1 ไม่ใช่ execution routing จริง

7. Runtime Manager

ใช้งานได้จริง

หน้าที่: เก็บรายการ runtime, readiness, integration mode, execution notes และ default runtime

  • ใช้เมื่อไร: ต้องการบอกว่าทีมใช้ runtime อะไร และ runtime ไหนเป็นค่าปริยาย
  • ปุ่ม/ช่องสำคัญ: Runtime name, Runtime type, Integration mode, Execution notes, Require approval, Save Runtime, Toggle Default
  • ขั้นตอนสั้น: เพิ่ม runtime ใหม่ → กำหนด requires approval → ตั้ง default ถ้าจำเป็น
  • ข้อควรระวัง: readiness ในหน้านี้ยังเป็นการ track ความพร้อม ไม่ใช่การ launch runtime จริง

8. Task Board

ใช้งานได้จริง

หน้าที่: ขับ manual/mock delivery loop ตั้งแต่สร้าง task ไปจนถึง review/audit/done

  • ใช้เมื่อไร: ต้องการเริ่มวิ่งงาน, สร้าง acceptance criteria, หรือทดลอง runtime planning flow
  • ปุ่ม/ช่องสำคัญ: Seed Initial Task Board, Generate Demo / Handoff Checklist, Create Task, Prepare Runtime Brief, Create Approval Request, Create Scope Request, Create Auth Request, Queue Launch Approval, Start Mock Run
  • ขั้นตอนสั้น: เลือกโปรเจกต์ → seed board หรือสร้าง task → เปิดการ์ดงาน → ใช้ปุ่ม transition ตามสถานะ
  • ข้อควรระวัง: Task transitions มีผลต่อ Run Log และ Human Request Inbox; การกด Start Mock Run คือเปลี่ยนสถานะ ไม่ได้ execute CLI จริง

9. Run Log

ใช้งานได้จริง

หน้าที่: แสดง execution trace ของ task transitions และการเตรียม runtime brief

  • ใช้เมื่อไร: ต้องการย้อนดูว่า task เคยผ่านสถานะอะไร หรือมีไฟล์ brief/log อะไรถูกเตรียมไว้
  • ปุ่ม/ช่องสำคัญ: Project filter, list ของ logs, logText แบบ monospaced
  • ขั้นตอนสั้น: เลือกโปรเจกต์ → เปิดอ่าน log ล่าสุด → ใช้เป็นหลักฐานตรวจสอบกระบวนการ
  • ข้อควรระวัง: log นี้สะท้อน planning/mock events ไม่ใช่ stdout จาก agent จริงใน V1 ปัจจุบัน

10. Human Request Inbox

ใช้งานได้จริง

หน้าที่: เก็บ approval gates, blocked launches, manual requests และการตอบกลับจากมนุษย์

  • ใช้เมื่อไร: เมื่อ runtime ต้องรออนุมัติ, ต้องยืนยัน scope, auth หรือมีคำถามบล็อกการทำงาน
  • ปุ่ม/ช่องสำคัญ: Create Request, Status picker, Response / decision note, Approve, Need Clarification, Cancel Request, Reopen
  • ขั้นตอนสั้น: สร้าง request ใหม่หรือรับ request จาก Task Board → ใส่ response → กด action ที่เหมาะสม
  • ข้อควรระวัง: request ที่เป็น blocking และยังไม่ resolved/cancelled จะกันการปิดโปรเจกต์

11. Demo / Handoff Center

ใช้งานได้จริง

หน้าที่: รวมทุกอย่างสำหรับ milestone demo/handoff เช่น checklist, demo script, handoff checklist, closure summary, known limitations, close project

  • ใช้เมื่อไร: ใกล้ส่งมอบ, ต้องเตรียมเอกสารสาธิต หรือปิดโปรเจกต์
  • ปุ่ม/ช่องสำคัญ: Generate Checklist, Generate Demo Script, Handoff Checklist, Export Summary, Close Project, Open Folder, Save Known Limitations, Save Item
  • ขั้นตอนสั้น: เลือกโปรเจกต์ → บันทึก known limitations → สร้าง demo/handoff artifacts → export summary → ปิดโปรเจกต์ถ้าไม่มี blocking requests
  • ข้อควรระวัง: Close Project จะไม่สำเร็จถ้ายังมี blocking requests เปิดอยู่

สถานะโปรเจกต์

draft

เพิ่งสร้างโปรเจกต์ ยังไม่ได้ผูก PRD หรือเริ่ม workflow ต่อ

prd_uploaded

มีการอ้างถึงช่วง PRD uploaded ในระบบ แต่ flow ปัจจุบันหลัง import จะขยับไป prd_analyzed เป็นหลัก

prd_analyzed

นำเข้า PRD แล้ว และสร้าง normalized markdown + analysis artifacts แล้ว

team_selected

มีการเลือกทีม/โครงสร้างทีมแล้ว

task_generated

มี task board หรือ seed task เกิดขึ้นแล้ว

in_progress

กำลังวิ่งงานจริงในระดับ workflow แม้ V1 ยังเป็น mock/manual loop

review / revision

งานอยู่ในช่วง review หรือถูกตีกลับไปแก้

demo_ready / demo_sent

พร้อมสาธิตหรือส่งออกสำหรับเดโมแล้ว

handoff_ready

ใกล้พร้อมส่งมอบ package

closed

ปิดโปรเจกต์แล้วหลังผ่าน closure gate

archived

เก็บ record ไว้เป็นประวัติ แต่ไม่ใช่งาน active

สถานะ ความหมาย ปุ่มที่มักใช้ต่อ

awaiting_approvalรอคนอนุมัติก่อนเริ่มApproval Received / Mark Launch Blocked / Cancel Launch Plan
launch_blockedเริ่มไม่ได้เพราะ scope/auth/approval ติดRetry Approval Gate / Cancel Launch Plan

reviewกำลัง review ผลงานSend to Audit / Request Fix
auditตรวจความพร้อมปิดงาน/ส่งมอบPass Audit / Need Human Input

cancelledยกเลิกแผนวิ่งงานReset
doneงานผ่าน audit แล้วReset (ถ้าต้องเริ่มใหม่)

Tips การใช้งานจริง

Tip 1 — เริ่มจาก Dashboard ทุกครั้ง

ถ้าคุณกลับมาทำงานต่อหลังพัก ให้เริ่มจาก Dashboard เพื่อเช็กว่า project ไหนยัง active, ไหน archived, และ workspace ไหนมี missing folders

Tip 2 — ใช้ PRD Import ให้ครบก่อนสร้าง task เอง

การ import PRD ก่อนจะช่วยให้ normalized path และ analysis artifacts พร้อมใช้งานสำหรับทีมและงานต่อไป

Tip 3 — ใช้ Seed Initial Task Board เป็น baseline

หากยังไม่มี task setup ให้ใช้ seed board ก่อน แล้วค่อยแตกงานเพิ่มเองตาม acceptance criteria จริง

Tip 4 — อย่าสับสนว่า Start Mock Run = launch agent จริง

ปุ่มนี้แค่เปลี่ยนสถานะและบันทึก workflow ภายใน V1 ไม่ได้สั่ง Codex/Claude/Gemini ให้ทำงานจริง

Tip 5 — ถ้าจะ close project ให้เคลียร์ Inbox ก่อน

Human Request ที่เป็น blocking และยังไม่ resolved/cancelled จะทำให้ปิดโปรเจกต์ไม่ผ่าน

Tip 6 — ใช้ Edit ก่อนค่อยลบ

ตอนนี้ Agent/Skill/Team รองรับการแก้ไขจากรายการแล้ว ถ้าต้องการปรับชื่อ, workflow หรือ project assignment ให้กด Edit ก่อน เพื่อลดการสร้าง record ซ้ำโดยไม่จำเป็น

ข้อจำกัด V1

  • ยังไม่มีการ launch agent CLI จริงจากในแอป
  • Runtime Manager เป็นการ track ความพร้อม/นโยบาย ไม่ใช่ execution engine
  • Agent Library, Skill Library, Team Builder ยังไม่มี edit flow แบบเต็ม
  • Task Board เป็น manual/mock state machine มากกว่าระบบ orchestration จริง
  • Run Log ตอนนี้สะท้อน workflow events และการเตรียม artifacts มากกว่าผลลัพธ์จาก subprocess จริง
  • การปิดโปรเจกต์ขึ้นกับ Human Request gates และ closure summary export
