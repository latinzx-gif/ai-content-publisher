📦 รายละเอียด Features (10 Modules)

M

Master Data — ข้อมูลหลัก

Must HaveP1

📦 สินค้า / SKU

ข้อมูลพื้นฐานของสินค้าหรือวัตถุดิบแต่ละรายการ

  • รหัสสินค้า (SKU Code) — Auto Generate หรือกำหนดเอง
  • ชื่อสินค้า (ไทย/อังกฤษ)
  • หมวดหมู่สินค้า (ผักสด, เนื้อสัตว์, เครื่องปรุง, บรรจุภัณฑ์ ฯลฯ)
  • หน่วยนับหลัก (กิโลกรัม, ลิตร, ลัง, ชิ้น, ถุง ฯลฯ)
  • Barcode / QR Code สำหรับสแกน
  • Min Stock Level — จุดเตือนเมื่อสต๊อกต่ำ
  • Max Stock Level — สำหรับวางแผนการสั่งซื้อ
  • รูปภาพสินค้า (optional)
  • สถานะ: ใช้งาน / ระงับ / เลิกใช้

🏢 สาขา / คลัง

โครงสร้างสถานที่จัดเก็บสินค้า

  • จัดการสาขา (Branch) — ร้านแต่ละสาขา
  • จัดการคลัง (Warehouse) — แต่ละสาขามีกี่คลัง
  • คลังหลัก (Main Warehouse) / คลังย่อย (Sub Warehouse)
  • ที่อยู่คลัง / ผู้รับผิดชอบ

🤝 Supplier

ข้อมูลผู้ขาย / คู่ค้า

  • รหัส Supplier, ชื่อ, ที่อยู่, เบอร์โทร
  • เงื่อนไขการชำระเงิน
  • สินค้าที่ Supplier รายนี้จัดส่ง

📐 หน่วยนับ / Conversion

หน่วยนับและการแปลงหน่วย

  • หน่วยนับหลักและหน่วยย่อย (เช่น ลัง = 12 ชิ้น, กิโลกรัม = 1000 กรัม)
  • รองรับหลายหน่วยนับต่อ SKU
  • Conversion Rate สำหรับการตัดสต๊อกข้ามหน่วย

📋 สูตรอาหาร / BOM

ส่วนประกอบของอาหารแต่ละเมนู สำหรับตัดสต๊อกอัตโนมัติ

  • เมนูอาหาร (Product) → วัตถุดิบ (Component)
  • ปริมาณที่ใช้ต่อหน่วย (เช่น ก๋วยเตี๋ยว 1 ชาม ใช้เส้น 200g)
  • ของเสีย / สูญเสียระหว่างการผลิต (%)
  • ใช้สำหรับคำนวณการตัดสต๊อกตามจำนวนขาย
1

รับสินค้าเข้าคลัง (Inbound)

Must HaveP1

📥 สร้างรายการรับสินค้า

  • สร้างเอกสารรับสินค้าเข้า (Goods Receipt Note)
  • เลือก Supplier / ใบส่งของ / เลขที่เอกสารอ้างอิง
  • วันที่รับสินค้า, สาขา, คลังปลายทาง
  • ระบุ SKU, จำนวนรับจริง, หน่วยนับ
  • บันทึกต้นทุนต่อหน่วย (ราคาซื้อ) ถ้าต้องการ
  • บันทึก Lot Number และวันหมดอายุ (Expiry Date)
  • สแกน Barcode เพื่อเพิ่มสินค้าเร็วขึ้น
  • แนบรูปสินค้า / ใบส่งของ / เอกสารประกอบ
  • บันทึกหมายเหตุ / รายการผิดปกติ

✅ การยืนยันและตรวจสอบ

  • บันทึกเป็น Draft → รอตรวจสอบ → อนุมัติเข้า Stock
  • เมื่ออนุมัติ: อัปเดต Stock Balance + Lot Balance
  • สามารถยกเลิก / แก้ไขรายการก่อนอนุมัติ
  • ประวัติการแก้ไข (Audit Trail) ทุกครั้งที่มีการเปลี่ยนแปลง
📌 Acceptance: สร้างรายการรับเข้า → ระบุ SKU, จำนวน, Lot, วันหมดอายุ, Supplier → เมื่ออนุมัติ ยอดคงเหลือเพิ่มขึ้นถูกต้อง
2

เบิกวัตถุดิบเข้าครัว (Kitchen Requisition)

Must HaveP1

📝 สร้างใบเบิก

  • หัวหน้าครัวสร้างใบเบิกวัตถุดิบ
  • ระบุสาขา, ผู้เบิก, วันที่ต้องการ
  • เลือก SKU + จำนวนที่ต้องการเบิก
  • ระบบแสดงยอดคงเหลือปัจจุบันขณะเบิก
  • บันทึกหมายเหตุ (optional)

✅ อนุมัติและจ่ายสินค้า

  • หัวหน้าคลัง / ผู้อนุมัติตรวจสอบรายการเบิก
  • อนุมัติ / อนุมัติบางส่วน / ไม่อนุมัติ
  • เจ้าหน้าที่คลังจ่ายสินค้าตามที่อนุมัติ
  • บันทึกการจ่าย: จำนวนที่จ่ายจริง, Lot ที่เบิก
  • อัปเดต Stock Balance ทันทีเมื่อจ่าย

📬 ยืนยันรับของจากครัว

  • หัวหน้าครัวยืนยันรับสินค้าที่เบิก
  • บันทึกจำนวนที่รับจริง (กรณีได้รับไม่ครบ)
  • ระบบบันทึก Movement และประวัติ
📌 Acceptance: สร้างใบเบิก → อนุมัติ → จ่ายสินค้า → ครัวยืนยันรับ → ระบบบันทึก Movement ออกถูกต้อง
3

ตัดสต๊อกตามการใช้งาน (Consumption & Damage)

Must HaveP1

📊 รายงานการใช้จริง (Consumption)

  • หัวหน้าครัวรายงานการใช้วัตถุดิบจริง รายวัน / รายสัปดาห์
  • ระบุ SKU + จำนวนที่ใช้จริง
  • ระบบตัด Stock balance ตามจำนวนที่รายงาน
  • รองรับการตัดตามสูตรอาหาร (BOM) — ใช้จำนวนขาย x ปริมาณต่อหน่วย
  • บันทึกประเภทการใช้งาน: ประกอบอาหาร, ทดสอบสูตร, ของตัวอย่าง

⚠️ ของชำรุด / เสียหาย / หมดอายุ (Damage & Spoilage)

  • บันทึกแยกประเภท: ชำรุด, เสียหาย, หมดอายุ, สูญหาย, ปรับปรุงยอด
  • ระบุจำนวน สาเหตุ ผู้บันทึก วันที่เกิดเหตุ
  • แนบรูปหลักฐาน (ถ่ายหน้างานผ่านมือถือ)
  • รองรับสถานะรออนุมัติ สำหรับกรณีผิดปกติ / เกินเกณฑ์
  • เส้นทางอนุมัติ: เจ้าหน้าที่ → หัวหน้าคลัง → Admin (ตามมูลค่า)

📋 รายงานแยก: ใช้จริง vs สูญเสีย

  • รายงาน Consumption แยกจาก Damage/Spoilage
  • เพื่อให้ผู้บริหารวิเคราะห์ต้นทุนจริง ≠ การสูญเสีย
  • Stock Adjustment แต่ละประเภทมีรหัสอ้างอิงของตัวเอง
📌 Acceptance: บันทึกการใช้จริง → ระบบลด Stock Balance — บันทึกชำรุด/เสียหาย แยกรายงาน พร้อมรูปหลักฐานและเส้นทางอนุมัติ
4

ตรวจนับสต๊อก (Stock Count)

Must HaveP1

📋 สร้างแผนตรวจนับ

  • กำหนดรอบตรวจนับ: รายวัน / รายสัปดาห์ / รายเดือน / ตามต้องการ
  • ระบุขอบเขต: คลังเป้าหมาย, สาขา, หมวดสินค้า, เฉพาะ SKU ที่เลือก
  • ระบบสร้างรายการ SKU ที่ต้องนับตามขอบเขต

📱 บันทึกผลตรวจนับ (Mobile / PDA)

  • เจ้าหน้าที่คลังสแกน Barcode / QR เพื่อค้นหา SKU
  • บันทึกจำนวนที่นับได้จริง (Physical Count)
  • ระบุ Lot ที่พบ / วันหมดอายุ
  • บันทึกหมายเหตุ (optional)

📊 เปรียบเทียบและปรับปรุง

  • ระบบคำนวณส่วนต่าง: ยอดในระบบ — ยอดนับจริง
  • แสดงรายการที่เกิน / ขาด พร้อมมูลค่าส่วนต่าง
  • สร้างรายการปรับปรุงสต๊อก (Adjustment) อัตโนมัติเมื่อยืนยัน
  • บันทึก Audit Trail: ใครนับ, ใครตรวจสอบ, ใครอนุมัติปรับปรุง
📌 Acceptance: สร้างแผนตรวจนับ → นับหน้างานผ่านมือถือ → ระบบเปรียบเทียบยอด → สร้าง Adjustment
5

โอนสินค้าระหว่างสาขา (Transfer)

Must HaveP1

📤 สร้างใบโอน (ต้นทาง)

  • หัวหน้าคลังสร้างใบโอนสินค้า
  • ระบุสาขาต้นทาง, สาขาปลายทาง, คลัง
  • เลือก SKU + จำนวน + Lot ที่ต้องการโอน
  • บันทึกวันที่โอน, ผู้ขนส่ง (option)
  • เมื่อสร้าง: สถานะ = "กำลังโอน" (ยอดถูกจอง)

📥 รับสินค้าปลายทาง

  • สาขาปลายทางยืนยันรับสินค้า
  • บันทึกจำนวนที่รับจริง (กรณีได้รับไม่ครบ / เสียหาย)
  • แนบรูปหลักฐาน (ถ้ามี)
  • เมื่อยืนยัน: อัปเดต Stock Balance ทั้ง 2 สาขาอัตโนมัติ
  • สถานะ: "กำลังโอน" → "รับแล้ว" / "ยกเลิก"
📌 Acceptance: สร้างใบโอน → สาขาต้นทางตัดยอด → ปลายทางรับ → อัปเดตสต๊อกทั้ง 2 สาขา
6

การแจ้งเตือน (Alerts & Notifications)

Should HaveP1

⏰ สินค้าใกล้หมดอายุ

  • แจ้งเตือนล่วงหน้า: 30 วัน / 14 วัน / 7 วัน / 1 วัน
  • แสดงรายการ Lot ที่กำลังจะหมดอายุ เรียงตามวันที่
  • กรองตามสาขา, คลัง, หมวดสินค้า, Supplier
  • แสดงมูลค่ารวมของ Lot ที่ใกล้หมดอายุ

📉 สินค้าต่ำกว่า Min Stock

  • SKU ใดที่คงเหลือ ≤ Min Stock Level
  • แสดงจำนวนที่ต้องสั่งซื้อเพิ่ม (Reorder Quantity)
  • แยกตามสาขา / คลัง

⚠️ รายการผิดปกติ

  • Stock Adjustment ผิดปกติที่รออนุมัติ
  • ส่วนต่างตรวจนับสูงเกินเกณฑ์
  • Damage/Spoilage มูลค่าสูงผิดปกติ
7

Dashboard ผู้บริหาร

Must HaveP1

📊 KPI หลัก

  • มูลค่าสต๊อกคงเหลือรวม (Total Inventory Value)
  • จำนวน SKU คงเหลือทั้งหมด
  • จำนวน SKU ที่ต่ำกว่า Min Stock
  • จำนวน SKU ที่ใกล้หมดอายุ
  • มูลค่าการสูญเสีย (Damage/Spoilage) รอบนี้

📈 กราฟแนวโน้ม

  • แนวโน้มมูลค่าสต๊อก รายวัน / รายสัปดาห์ / รายเดือน
  • แนวโน้มการรับเข้า vs การเบิกใช้
  • แนวโน้มการสูญเสีย / ชำรุด
  • สัดส่วนมูลค่าสินค้าแยกตามหมวดหมู่

🔍 รายการล่าสุด

  • รายการรับเข้าล่าสุด 10 รายการ
  • รายการเบิกล่าสุด 10 รายการ
  • รายการโอนที่กำลังดำเนินการ
  • รายการ Adjustment ล่าสุด

รายงาน (Reports)

Must HaveP1

📄 ประเภทรายงาน

รายงานหลักที่ระบบต้องรองรับ

  • Stock On Hand Report — ยอดคงเหลือปัจจุบัน
  • Inbound Report — รายการรับเข้าตามช่วงเวลา
  • Kitchen Requisition Report — รายการเบิก
  • Consumption Report — การใช้จริง แยกตาม SKU/สาขา
  • Damage / Spoilage Report — การสูญเสีย แยกตามประเภท สาเหตุ
  • Expiry Report — สินค้าใกล้หมดอายุ
  • Transfer Report — การโอนระหว่างสาขา
  • Stock Count Variance Report — ส่วนต่างตรวจนับ
  • Audit Trail Report — ประวัติการเปลี่ยนแปลงทั้งหมด

⚙️ ฟังก์ชันรายงาน

  • กรองตาม: ช่วงเวลา, สาขา, คลัง, หมวดสินค้า, SKU
  • Export: รองรับไฟล์ Excel / CSV / PDF
  • แสดงยอดรวม และมูลค่ารวมท้ายรายงาน

Mobile / PDA / Barcode Support

Should HaveP1

📱 อุปกรณ์ที่รองรับ

  • Web Application (PC) สำหรับ Admin และผู้บริหาร
  • Mobile Web Responsive สำหรับพนักงานหน้างาน (iOS/Android)
  • PDA Scanner สำหรับคลังและการตรวจนับ
  • กล้องมือถือสำหรับสแกน Barcode / QR Code

🎯 Use Case บนมือถือ

  • รับสินค้าเข้าโดยสแกน Barcode
  • เบิกจ่ายสินค้าเข้าครัวผ่านมือถือ
  • ตรวจนับสต๊อกหน้างาน (Scan + นับ)
  • ถ่ายรูปแนบหลักฐานกรณีสินค้าเสียหาย / ชำรุด
  • ยืนยันรับสินค้าโอนระหว่างสาขา
  • ดู Dashboard และรายงานสรุป (Read-only)

✅ Acceptance Criteria

FeatureAcceptance
รับสินค้าเข้าสร้างรายการ → ระบุ SKU, จำนวน, Lot, วันหมดอายุ, Supplier → อนุมัติ → ยอดคงเหลือเพิ่ม
เบิกเข้าครัวสร้างใบเบิก → อนุมัติ → จ่ายสินค้า → ครัวยืนยันรับ → Movement ออกถูกต้อง
ตัดสต๊อกใช้จริงบันทึกการใช้จริง → ระบบลด Stock Balance ตามจำนวนหรือสูตร
ชำรุด/เสียหายบันทึกพร้อมเหตุผล+รูป → รายงานแยกจากการใช้จริง → เส้นทางอนุมัติ
ตรวจนับสร้างแผน → นับผ่านมือถือ → เปรียบเทียบ → สร้าง Adjustment
แจ้งเตือนแสดงรายการใกล้หมดอายุ + ต่ำกว่า Min Stock + รายการผิดปกติ
Dashboardผู้บริหารดูภาพรวมสต๊อก การใช้ การสูญเสีย แนวโน้ม
สิทธิ์ผู้ใช้แต่ละ Role เห็นเมนูและทำรายการตามสิทธิ์ที่กำหนด
